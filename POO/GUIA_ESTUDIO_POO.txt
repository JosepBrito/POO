A.1 DEF (FUNCIONES) [ACTUALIZADO]
- DEFINICION: Palabra clave para declarar funciones o bloques de codigo reutilizables.
- ANALOGIA: Una receta de cocina guardada para usar cada vez que quieras preparar una comida.
- EJEMPLO DE CODIGO:
  def saludar(nombre):
      return f"Hola, {nombre}"

  print(saludar("Carlos"))

A.2 CLASS (CLASES) [ACTUALIZADO]
- DEFINICION: Palabra clave para definir una clase (molde o plantilla de objetos).
- ANALOGIA: El plano de construccion de un edificio.
- EJEMPLO DE CODIGO:
  class Persona:
      pass

  persona1 = Persona()

A.3 SELF (REFERENCIA A LA INSTANCIA) [NUEVO]
- DEFINICION: Representa al objeto concreto actual dentro de los metodos de la clase.
- ANALOGIA: El pronombre "mi" (mi nombre, mi edad, mi saldo).
- EJEMPLO DE CODIGO:
  class Estudiante:
      def __init__(self, nombre):
          self.nombre = nombre

A.4 RETURN (RETORNO DE VALOR) [NUEVO]
- DEFINICION: Devuelve el resultado de la ejecucion de una funcion o metodo al invocador.
- ANALOGIA: Pedir un producto y que el mesero te entregue el pedido terminado.
- EJEMPLO DE CODIGO:
  def sumar(a, b):
      return a + b

A.5 SUPER() (INVOCACION A LA CLASE PADRE) [NUEVO]
- DEFINICION: Permite llamar a metodos (especialmente `__init__`) de la clase padre desde la clase derivada.
- ANALOGIA: Consultar el libro de conocimientos de tus padres antes de agregar tu propia idea.
- EJEMPLO DE CODIGO:

      def __init__(self, marca, modelo):

A.7 TRY / EXCEPT (MANEJO DE EXCEPCIONES) [NUEVO]

- ANALOGIA: Una red de seguridad colocada debajo de un trapecista.
- EJEMPLO DE CODIGO:

      edad = int("veinte")

A.8 IF / ELSE (CONTROL CONDICIONAL) [NUEVO]
- DEFINICION: Evalua una condicion logica para tomar distintos caminos de ejecucion.
- ANALOGIA: Un semaforo: si esta verde avanzas, si esta rojo te detienes.

- ANALOGIA: Dejar una hoja en blanco con una nota de "proximamente" mientras terminas de redactar.
- EJEMPLO DE CODIGO:

1.1 PROGRAMACION ESTRUCTURADA VS POO (`programacion_estructurada.py`) [ACTUALIZADO]
- DEFINICION:
  La programacion estructurada separa la logica (funciones) de los datos (variables). 
  La POO los agrupa en objetos que combinan estado y comportamiento.
- ANALOGIA / EXPLICACION SIMPLE:
  Estructurada: Tener ingredientes sueltos por la mesa y las herramientas en otra esquina. 
  POO: Tener kits cerrados donde cada caja trae su ingrediente y la herramienta exacta para procesarlo.
- PARA QUE SIRVE / CUANDO SE USA:
  Se usa la POO para evitar variables globales desordenadas y gestionar proyectos de software grandes.
- EXPLICACION DEL CODIGO PASO A PASO (`programacion_estructurada.py`):
  1. `def mostrar_empleado(nombre, cargo, salario):` -> Funcion independiente que recibe variables sueltas y las imprime.
  2. `def calcular_salario_anual(salario):` -> Multiplica el valor por 12 y retorna el resultado.
  3. `def aumentar_salario(salario, porcentaje):` -> Retorna un nuevo salario sumando el porcentaje.
  4. Bloque ejecutable: Se definen variables sueltas `nombre = "Carlos"`, `cargo = "Tecnico"`, `salario = 1800` y se pasan manualmente a cada funcion.
- EJERCICIOS PRACTICOS CON SOLUCION:
  * Ejercicio 1: Convertir una funcion estructurada de calcular impuestos a una clase POO.
    Solucion:
    class Producto:
        def __init__(self, precio):
            self.precio = precio
        def calcular_impuesto(self):
            return self.precio * 0.18

1.2 ABSTRACCION (`abstraccion.py`) [ACTUALIZADO]
- DEFINICION:
  Consiste en seleccionar unicamente los atributos y metodos esenciales de una entidad, ignorando los detalles irrelevantes para el problema actual.
- ANALOGIA / EXPLICACION SIMPLE:
  El panel de un automovil: solo muestra velocidad, combustible y temperatura, ocultando el mapa de circuitos electronicos del motor.
- PARA QUE SIRVE / CUANDO SE USA:
  Para simplificar modelos de datos complejos y reducir la carga cognitiva al programar.
- EXPLICACION DEL CODIGO PASO A PASO (`abstraccion.py`):
  1. `class Empleado:` -> Define la plantilla con atributos esenciales: `nombre`, `cargo` y `salario`.
  2. `def __init__(self, nombre, cargo, salario):` -> Asigna los datos iniciales al objeto actual.
  3. `def mostrar_datos(self):` -> Imprime la ficha del empleado accediendo a sus atributos internos.
  4. `def aumentar_salario(self, porcentaje):` -> Modifica `self.salario` aplicando el porcentaje.
  5. `empleado1 = Empleado("Carlos", "Tecnico de Sistemas", 1800)` -> Instancia el objeto abstracto.
  6. `empleado1.aumentar_salario(10)` -> Aplica la logica sin preocuparse por la implementacion interna.
- EJERCICIOS PRACTICOS CON SOLUCION:
  * Ejercicio 1: Modela una clase `Celular` usando abstraccion (atributos: marca, bateria; metodo: usar).
    Solucion:
    class Celular:
        def __init__(self, marca, bateria):
            self.marca = marca
            self.bateria = bateria
        def usar(self, horas):
            self.bateria -= horas * 10

1.3 ENCAPSULAMIENTO BASICO (`encapsulamiento.py`) [ACTUALIZADO]
- DEFINICION:
  Tecnica para ocultar el estado interno de un objeto (usando `__`) y ofrecer acceso controlado mediante metodos.
- ANALOGIA / EXPLICACION SIMPLE:
  Un cajero automatico: no puedes tomar el dinero directamente de la caja fuerte; debes interactuar a traves de la pantalla y la clave.
- PARA QUE SIRVE / CUANDO SE USA:
  Para prevenir alteraciones accidentales o no autorizadas en los datos sensibles de un objeto.
- EXPLICACION DEL CODIGO PASO A PASO (`encapsulamiento.py`):
  1. `self.__salario = salario` -> El doble guion alto/bajo oculta el atributo fuera de la clase.
  2. `def obtener_salario(self):` -> Getter que retorna el valor encapsulado de `self.__salario`.
  3. `def aumentar_salario(self, porcentaje):` -> Setter que modifica el salario encapsulado con una formula.
  4. `empleado = Empleado("Chantal", "Nutricionista", 2300)` -> Crea la instancia.
  5. `empleado.obtener_salario()` -> Consulta el valor a traves del metodo publico.
- EJERCICIOS PRACTICOS CON SOLUCION:
  * Ejercicio 1: Crear la clase `CajaFuerte` con atributo privado `__clave`.
    Solucion:
    class CajaFuerte:
        def __init__(self, clave):
            self.__clave = clave
        def verificar(self, intento):
            return self.__clave == intento

1.4 HERENCIA BASICA (`herencia.py`) [ACTUALIZADO]
- DEFINICION:
  Mecanismo que permite a una clase hija adquirir los atributos y metodos de una clase padre o base.
- ANALOGIA / EXPLICACION SIMPLE:
  Un arbol genealogico: el hijo hereda rasgos biologicos de los padres y ademas adquiere habilidades propias.
- PARA QUE SIRVE / CUANDO SE USA:
  Para evitar duplicar codigo entre clases que comparten una relacion jerarquica de tipo "ES UN".
- EXPLICACION DEL CODIGO PASO A PASO (`herencia.py`):
  1. `class Empleado:` -> Clase padre que define `nombre` y `salario`.
  2. `class EmpleadoTecnico(Empleado):` -> Clase hija que deriva de `Empleado`.
  3. `super().__init__(nombre, salario)` -> Llama al constructor padre para reutilizar su inicializacion.
  4. `self.especialidad = especialidad` -> Agrega un atributo exclusivo de la clase derivada.
- EJERCICIOS PRACTICOS CON SOLUCION:
  * Ejercicio 1: Crear clase `Vehiculo` y subclase `Moto` con atributo `cilindrada`.
    Solucion:
    class Vehiculo:
        def __init__(self, marca): self.marca = marca
    class Moto(Vehiculo):
        def __init__(self, marca, cilindrada):
            super().__init__(marca)
            self.cilindrada = cilindrada

1.5 POLIMORFISMO BASICO (`polimorfismo.py`) [ACTUALIZADO]
- DEFINICION:
  Capacidad de diferentes objetos de responder a la misma llamada de metodo ejecutando su propia implementacion.
- ANALOGIA / EXPLICACION SIMPLE:
  Presionar el boton de reproduccion ("Play") en Spotify, YouTube o reproductor de DVD: cada aparato reproduce segun su formato.
- PARA QUE SIRVE / CUANDO SE USA:
  Permite procesar colecciones mixtas de objetos mediante una interfaz comun.
- EXPLICACION DEL CODIGO PASO A PASO (`polimorfismo.py`):
  1. `EmpleadoTecnico` y `Gerente` heredan de `Empleado` y cada uno sobrescribe `mostrar_datos()`.
  2. `empleados = [EmpleadoTecnico(...), Gerente(...)]` -> Lista con objetos de distintos tipos.
  3. `for empleado in empleados: empleado.mostrar_datos()` -> Invoca la version del metodo correspondiente a la clase real de cada objeto.
- EJERCICIOS PRACTICOS CON SOLUCION:
  * Ejercicio 1: Crear `Circulo` y `Cuadrado` con el metodo polimorfico `dibujar()`.
    Solucion:
    class Circulo:
        def dibujar(self): print("Dibujando Circulo")
    class Cuadrado:
        def dibujar(self): print("Dibujando Cuadrado")
    lista = [Circulo(), Cuadrado()]
    for item in lista: item.dibujar()

PREGUNTA 1:
¿Cual es la diferencia en Python entre un atributo publico (`self.x`), uno protegido (`self._x`) y uno privado (`self.__x`)?
RESPUESTA 1:
- El publico se accede y modifica libremente sin restricciones.
- El protegido es una convencion visual de indicacion de uso interno/heredado; Python no impide su acceso directo.
- El privado sufre Name Mangling (se renombra como `_NombreClase__x`), generando un error `AttributeError` al intentar acceder directamente como `objeto.__x`.

PREGUNTA 2:
¿Para que se utiliza `super().__init__(...)` en una clase derivada?
RESPUESTA 2:
Para ejecutar el constructor de la clase base padre, asegurando que los atributos de la clase padre queden inicializados en la instancia hija sin duplicar codigo.

PREGUNTA 3:
¿Como se aplica el polimorfismo en una lista de objetos de distintas clases en Python?
RESPUESTA 3:
Invocando el mismo metodo en un bucle `for obj in lista: obj.metodo()`. Cada objeto ejecutara la version del metodo correspondiente a su clase.

PREGUNTA 4:
En Tkinter, ¿para que sirven los metodos `get()` y `delete(0, tk.END)` en un componente `Entry`?
RESPUESTA 4:
`get()` obtiene la cadena de texto escrita por el usuario, y `delete(0, tk.END)` borra la totalidad del texto presente en la caja de entrada.

PREGUNTA 5:
¿Que funcion cumple el bloque `try / except ValueError` en la validacion de formularios?
RESPUESTA 5:
Captura el error de conversion cuando un usuario ingresa texto en campos que requieren numeros (como edad o salario con `int()` o `float()`), evitando que el programa se detenga con un fallo fatal.
